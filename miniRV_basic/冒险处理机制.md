# 流水线冒险的检测与解决（cpu_core 分析）

本文档基于 [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v) 及其相关模块（[`NPC.v`](miniRV_basic/src/rtl/NPC.v)、[`PC.v`](miniRV_basic/src/rtl/PC.v)、[`Controller.v`](miniRV_basic/src/rtl/Controller.v)、[`RF.v`](miniRV_basic/src/rtl/RF.v)、[`ALU.v`](miniRV_basic/src/rtl/ALU.v)、[`cpu_top.v`](miniRV_basic/src/rtl/cpu_top.v)），说明流水线三大类冒险——**数据冒险、分支冒险（控制冒险）、取值（取指/IF 阶段）冒险**——是如何被检测和解决的。

---

## 0. 流水线总体结构

[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v) 实现经典五级流水线 RISC-V 核：

```
IF（取指）→ ID（译码/读寄存器）→ EX（执行/比较）→ MEM（访存）→ WB（写回）
```

各段之间的关键流水线寄存器：

| 段间 | 关键寄存器 | 位置 |
|---|---|---|
| IF/ID | `id_pc`、`id_inst`、`fetch_pc` | [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:216) |
| ID/EX | `ex_rd1`、`ex_rd2`、`ex_alu_op`、`ex_rf_wR`、`ex_rs1`、`ex_rs2`、`ex_npc_op` | [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:357) |
| EX/MEM | `mem_alu_c`、`mem_rf_we`、`mem_rf_wR`、`mem_pc`、`mem_ram_rop` | [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:486) |

特殊说明：
- `fetch_pc` 是取指请求地址 `ifetch_addr` 的 **1 拍延迟**，用于与 IROM 返回的 `ifetch_inst` 对齐（IROM 读延迟 1 拍），见 [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:219)。
- ID 段的源寄存器号必须取自 `id_inst`（流水线寄存器）而非 IF 段的 `inst`，否则暂停期间 `id_rs1/id_rs2` 会漂移，见 [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:230)。

## 1. 数据冒险（Data Hazard / RAW）

**问题**：流水线中，上一条指令的结果要等它走到 WB 才写入寄存器堆，而紧跟在后面的指令在 ID 阶段就要读这个寄存器，读到的会是旧值（RAW 冒险）。

### 1.1 冒险检测

检测"ID 阶段源寄存器是否与后面各段正在产生结果的目标寄存器冲突"，核心条件是"**目标==源 && 写使能 && ID 确实读该寄存器 && 目标不是 x0**"：

```verilog
// EX → ID 检测
assign rs1_id_ex_hazard = (ex_rf_wR == id_rs1) & ex_rf_we & id_rf1 & (ex_rf_wR != 5'h0);
assign rs2_id_ex_hazard = (ex_rf_wR == id_rs2) & ex_rf_we & id_rf2 & (ex_rf_wR != 5'h0);
```
见 [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:468)。

MEM 级和 WB 级同理：

| 级别 | 信号 | 位置 |
|---|---|---|
| EX→ID | `rs1_id_ex_hazard` / `rs2_id_ex_hazard` | [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:468) |
| MEM→ID | `rs1_id_mem_hazard` / `rs2_id_mem_hazard` | [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:681) |
| WB→ID | `rs1_id_wb_hazard` / `rs2_id_wb_hazard` | [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:799) |

其中 `id_rf1` / `id_rf2` 来自控制器，用于判断 ID 指令**是否真的读取** rs1/rs2：

```verilog
assign id_rf1 = !alua_sel & !JAL & !LUI;        // ALU A 用 rs1，且不是 JAL/LUI
assign id_rf2 = (!alub_sel | SB | SH | SW) & !LUI; // ALU B 用 rs2，或 Store 读 rs2
```
见 [`Controller.v`](miniRV_basic/src/rtl/Controller.v:265)。这里排除 LUI（LUI 的立即数位段会充当伪寄存器号，可能误触发冒险）和 JAL（不读源寄存器）。

### 1.2 解决方式一：数据前递（Forwarding / Bypassing）

普通 RAW 冒险（ALU/LUI/JAL 等结果在 EX/MEM/WB 已经就绪）**全部靠前递解决，不停顿**。前递检测见 [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:802)。

三级前递，优先级 **EX > MEM > WB > 寄存器堆原值**：

```verilog
assign fwd_r1 = fwd_ex_rs1 ? ex_fwd_val :
                fwd_mem_rs1 ? mem_fwd_val :
                fwd_wb_rs1  ? rf_wD :
                              rf_rd1;
```
见 [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:825)。

- **EX 前递**（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:807)）：`fwd_ex_rs1` 命中条件中带 `!ex_is_load`——**排除 load**，因为 load 的结果要到 MEM 才返回。前递值 `ex_fwd_val` 按写回来源分源（LUI→`ex_ext`，JAL/JALR→`ex_pc+4`，其余→`alu_c`），见 [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:810)。
- **MEM 前递**（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:819)）：条件含 `mem_data_ok`，即 MEM 中 load 的 `daccess_rvalid` 已到达才前递；前递值 `mem_fwd_val` 同样分源（load→`ram_ext`，LUI→`mem_ext`，JAL→`mem_pc+4`，其余→`mem_alu_c`），见 [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:814)。
- **WB 前递**（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:822)）：最低优先级，WB 事件 `rf_we1` 成立时 `rf_wD` 即为正在写回的数据。

前递后的 `fwd_r1`/`fwd_r2` 在 ID/EX 捕获时写入 `ex_rd1`/`ex_rd2`，见 [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:444)。

### 1.3 解决方式二：停顿（Stall）

前递解决不了的冒险（数据还没产生）才停顿：

**(a) load-use 冒险**（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:839)）：

```verilog
assign load_use = ex_is_load &
                  ((ex_rf_wR == id_rs1) & id_rf1 | (ex_rf_wR == id_rs2) & id_rf2) &
                  (ex_rf_wR != 5'h0);
```

EX 中 load 的目标 == ID 源寄存器，数据要等 MEM 返回，前递不可行。处理方式：
1. 冻结 **ID/EX**（`mem_pipline_stop`），ID 中依赖指令保持；
2. **ID/EX 照常前进**：load 从 EX 进 MEM 发出访存请求，依赖指令以旧值（或前递值）进 EX；
3. EX 侧 **MEM 前递** `ex_mem_fwd1/ex_mem_fwd2`（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:652)）：数据到达（`mem_data_ok=1`）后，按 EX 自己的源寄存器号 `ex_rs1/ex_rs2` 重新前递，`alu_a`/`alu_b` 在 EX 重新计算：

```verilog
assign alu_a = ex_alu_a_sel ? ex_pc : (ex_mem_fwd1 ? mem_fwd_val : ex_rd1);
assign alu_b = ex_alu_b_sel ? ex_ext : (ex_mem_fwd2 ? mem_fwd_val : ex_rd2);
```
见 [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:654)。

**(b) MEM 中 load 数据未到且 ID 依赖它**（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:842)）：

```verilog
assign mem_ld_pending_hazard = (rs1_id_mem_hazard | rs2_id_mem_hazard) & !mem_data_ok;
```

触发**三路冻结**（PC+IF/ID、ID/EX、EX/MEM 全部停住），等 `daccess_rvalid` 到达。

**(c) 多周期访存冻结**：load/store 在 MEM 中等待 `daccess_rvalid`/`daccess_wresp`。`mem_ld_stall`（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:607)）冻结 EX/MEM 等 WB；配套 `ld_pending`/`ld_done`/`ld_dest`/`ld_pc_val` 完成链标识"哪条 load/store 在完成"，避免连续 ld/st 时身份错乱（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:575)）。

**(d) 乘除法完成链**：乘除是多周期运算，`mul_done_pulse`（busy 下降沿单拍）标记完成，`mul_div_stall` 冻结三路，`mul_post`/`mul_post2` 在完成后额外冻结 2 拍等 ALU 的 `op_r` 清除（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:610)）。

### 1.4 三路冻结信号汇总

| 冻结信号 | 冻结对象 | 位置 |
|---|---|---|
| `pipline_stop` | PC + IF/ID（ID 中指令不被覆盖） | [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:876) |
| `mem_pipline_stop` | ID/EX（EX 中指令不被后继覆盖） | [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:879) |
| `wb_pipline_stop` | EX/MEM（MEM 中指令驻留等数据） | [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:881) |

NPC 在 `pipline_stop` 时输出 `npc = pc`（PC 冻结），见 [`NPC.v`](miniRV_basic/src/rtl/NPC.v:18)；PC 仅在 `fetch` 使能时更新，见 [`PC.v`](miniRV_basic/src/rtl/PC.v:14)。

## 2. 分支冒险（控制冒险 / Control Hazard）

### 2.1 问题

分支/跳转要在 **EX 阶段**才完成求值（`br` 由 ALU 比较得出，JALR 目标由 ALU 加法得出），而 NPC 的译码取自 ID 阶段指令。当分支在 EX 解析时，ID 已经取入了分支的后继指令（顺序路径），这些指令是错误路径，必须丢弃并转向正确目标。

### 2.2 解决：EX 阶段分支重定向（D4）

见 [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:684) 注释与实现。

**(a) 判断是否需要重定向**（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:690)）：

```verilog
assign ex_bj_f = (ex_npc_op == `NPC_JMP) |
                 (ex_npc_op == `NPC_JALR) |
                 ((ex_npc_op == `NPC_BRA) & br);
```

EX 捕获了分支类型 `ex_npc_op`；B 型分支还需 `br`（ALU 比较结果）为真。

**(b) 计算目标地址**（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:693)）：

```verilog
assign ex_bj_target = (ex_npc_op == `NPC_JALR) ? {alu_c[31:1], 1'b0} :
                      (ex_pc + ex_ext);
```

JALR 用 ALU 加法结果（清最低位），其余用 `ex_pc + ex_ext`（ex_ext 是 EX 阶段锁存的立即数）。

**(c) 抑制条件：分支依赖未就绪的 load 数据**（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:702)）：

```verilog
assign ex_br_pending = mem_is_ld_st & !daccess_rvalid & mem_rf_we &
                       (mem_rf_wR != 5'h0) &
                       ((mem_rf_wR == ex_rs1) | (mem_rf_wR == ex_rs2));
```

若 EX 分支的源寄存器是 MEM 中 load 的目标且数据未到，`br` 由旧操作数求出（不可信），**抑制重定向**，等数据到达后 `fwd` 生效、`br` 重算再跳。

**(d) 重定向使能**（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:707)）：

```verilog
assign need_redirect = ex_bj_f & (ex_bj_target != id_pc) & !ex_br_pending;
```

目标 == `id_pc`（即目标恰好是分支+4，ID 中已持正确指令）时不重定向、不 flush。

### 2.3 重定向时的取指与 PC 处理

- **取指地址改向目标**：`ifetch_addr = need_redirect ? ex_bj_target : pc`（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:178)），`ifetch_req` 中也加入了 `need_redirect` 项强制发出目标请求（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:171)）。
- **PC 强制更新**：`PC` 的输入 `npc` 与使能 `fetch` 在 `need_redirect` 时强制为目标地址（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:201)），避免冻结期间丢失重定向。
- **flush 错误路径**：IF/ID 和 ID/EX 的复位条件中加入 `need_redirect`（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:240)、[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:378)），把已进入 ID/EX 的错误路径指令清成气泡（NOP）。
- **skip_fetch 防重复取指**（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:718)）：重定向拍已用目标地址请求了目标指令，下一拍 PC=目标地址，若照常取指会把目标指令**取两次**，故 `skip_fetch` 跳过 1 拍取指。

### 2.4 总线副本丢弃（dup-check）

重定向/冻结恢复期间，总线可能连续 2 拍返回同一地址的指令副本。IF/ID 捕获逻辑（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:249)）在"总线返回地址 == ID/EX/MEM 中已有指令地址"时判定为副本，**插入气泡丢弃**，防止指令被重复执行。

## 3. 取值（取指 / IF 阶段）冒险与取指流控制

**问题**：取指阶段要解决 3 类问题——(1) IROM 单拍延迟导致的指令与 PC 错位；(2) 多周期指令（访存/乘除）期间总线与流水线的协调；(3) 如何保证每条指令**恰好被捕获一次**（不重复、不丢失），并与 PC 前进严格同步。

### 3.1 取指接口与时序

取指接口为请求/应答式（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:9)）：

```verilog
ifetch_req    // 请求取指
ifetch_addr   // 请求地址
ifetch_valid  // IROM 返回有效（请求的 1 拍延迟）
ifetch_inst   // IROM 返回指令
```

- **1 拍延迟同步**：`fetch_pc` 锁存 `ifetch_addr` 的 1 拍延迟，与 `ifetch_inst` 对齐（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:223)）。若直接用当前 `pc` 作 ID 阶段 PC，会整体错位一条指令。
- **无效保护**：`inst = ifetch_valid ? ifetch_inst : NOP`（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:212)），避免 `ifetch_valid` 撤销后 `ifetch_inst` 变化导致执行出错。

### 3.2 取指暂停（pause_ifetch / resume_ifetch）

多周期指令（访存、乘除）在 MEM/EX 中等待结果期间，暂停取指总线（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:168)）：

```verilog
wire pause_ifetch  = (mem_is_ld_st | is_ld_st | ex_is_ld_st) & !ld_st_done;
wire resume_ifetch = ld_st_done | !mul_div_busy;
```

- 访存指令在 ID/EX/MEM 任一阶段且未完成时，`pause_ifetch=1` 禁止发出新取指请求；
- 完成（`ld_st_done`）或乘除结束（`!mul_div_busy`）时 `resume_ifetch=1` 继续取指。

### 3.3 PC 前进控制（inst_finished）

`inst_finished` 决定 PC 何时前进（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:909)）：

```verilog
assign inst_finished = ld_st_flag & ld_st_done |
                       mul_done_pulse & !id_is_mul_div |
                       (id_is_mul_div & !mul_div_wait & (pc == (id_pc + 32'h4)) & !mul_post & !mul_post2) |
                       ifetch_valid & !is_ld_st & !is_mul_div & (id_pc == fetch_pc) &
                       !mem_ld_stall & !ex_is_ld_st;
```

- 单周期指令：`ifetch_valid` 有效且 ID 阶段非多周期指令、ID 确实捕获了当前取指（`id_pc==fetch_pc`）且访存/乘除无冻结时 PC 前进；
- 访存指令：`ld_st_done` 时前进；
- 乘除指令：`mul_done_pulse` 完成脉冲时前进（连续乘除有专门处理，`mul_done_pulse & !id_is_mul_div` 排除 ID 仍是乘除的情况，防止 PC 把后继指令甩掉）。

`inst_finished_r` 锁存该信号供使用（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:936)）。

### 3.4 哈佛结构取指持续

乘除冻结期间取指**必须持续**：PC 冻结在乘除指令地址，总线反复返回该地址的指令副本（IF/ID 冻结挡住），乘除完成/气泡结束后 IF/ID 捕获它、PC 同步前进。若暂停总线会造成总线空隙（valid=0），恢复拍 IF/ID 捕获 NOP，乘除后继指令会永久丢失（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:161) 注释）。

### 3.5 指令只被捕获一次

取指流通过三层保证每条指令恰好执行一次：

1. **IF/ID 冻结**：`pipline_stop` 时 `id_pc/id_inst` 保持不变（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:245)），暂停期间总线返回的副本不覆盖 ID 中等待的指令；
2. **dup-check 气泡丢弃**：总线返回地址与 ID/EX/MEM 已有指令相同时插气泡（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:249)）；
3. **skip_fetch**：分支重定向拍后跳过 1 拍取指（[`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:718)），防止目标指令被取两次。

### 3.6 多周期访存的总线门控

load/store 请求只发 1 拍（进 MEM 首拍），避免驻留 MEM 期间每拍重发请求造成重复应答/重复 WB：

```verilog
daccess_ren <= (mem_is_ld_st & !ld_pending & !ld_done) ? da_ren : 4'h0;
```
见 [`cpu_core.v`](miniRV_basic/src/rtl/cpu_core.v:665)。

## 4. 总结

| 冒险类型 | 检测位置 | 解决手段 | 核心信号/机制 |
|---|---|---|---|
| **数据冒险（RAW）** | ID vs EX/MEM/WB 目标寄存器比较 | ① 数据前递（EX>MEM>WB）② load-use/数据未到/多周期指令停顿 | `fwd_ex/mem/wb_rs*`、`ex_fwd_val`、`mem_fwd_val`、`load_use`、`mem_ld_pending_hazard`、`pipline_stop`/`mem_pipline_stop`/`wb_pipline_stop` |
| **分支冒险（控制）** | EX 阶段捕获分支类型与目标 | EX 阶段分支重定向：目标地址取指 + flush IF/ID、ID/EX + skip_fetch 防重复取指 + ex_br_pending 防御 | `ex_bj_f`、`ex_bj_target`、`need_redirect`、`skip_fetch`、`ex_br_pending` |
| **取值（取指/IF）** | IF/ID 捕获逻辑 | ① fetch_pc 与 IROM 1 拍延迟对齐 ② pause/resume 协调多周期指令 ③ inst_finished 控制 PC 前进 ④ dup-check + skip_fetch 保证每条指令只捕获一次 ⑤ 总线门控只发单拍请求 | `fetch_pc`、`ifetch_req/valid/inst`、`pause_ifetch`、`inst_finished`、`skip_fetch`、`ld_pending` |

核心设计思想：**普通 RAW 冒险用前递（零开销）解决；只有数据尚未产生（load-use、多周期访存/乘除）才停顿；分支采用 EX 阶段重定向（比 ID 解码更准、比 MEM 阶段更早，代价是 flush 已进入 ID/EX 的错误路径指令）；取指流通过"请求-应答"接口、1 拍延迟对齐、暂停/恢复与 dup-check 三层保证取指与执行严格同步、每条指令恰好执行一次。**
